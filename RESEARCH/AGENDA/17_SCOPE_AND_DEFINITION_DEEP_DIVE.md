
# 17 — Deep Dive: Scope and Definition

## Core problem

The definition decides which technologies the international framework can regulate. It therefore cannot be treated as a preliminary wording exercise.

The 2026 GGE working text used a capability-based characterization built around a functionally integrated combination of weapons and technological components capable of **identifying, selecting and engaging a target without human intervention in the execution of those tasks**. The same working text also tried to prevent a human from excluding a system merely by setting broad target parameters, while creating an exclusion for systems where personnel choose the specific target(s) to be engaged.

The 2026 Chair's summary records substantial disagreement over whether the wording might accidentally capture existing fire-and-forget/homing systems, whether adding "identify" creates loopholes or overbreadth, and whether "lethal" should be an express part of the characterization.

## Definition dimensions

### 1. Platform vs function
A platform definition regulates objects such as drones, missiles or robots.

A functional definition regulates what the system does.

A capability-based functional characterization is more resistant to technological substitution because the same autonomy stack can move between physical platforms.

### 2. Critical functions
The debate can be decomposed into:
- detect;
- identify/classify;
- select;
- engage;
- assess effects;
- re-plan.

The politically and legally sensitive portion is the targeting/use-of-force chain.

### 3. Human target selection
One of the hardest scope questions is whether a system is autonomous when humans predefine:
- target classes;
- signatures;
- geographic areas;
- operating conditions;
but the system subsequently selects specific objects.

If a human picks the actual target, some proposals would place the system outside the LAWS characterization. If the machine chooses among targets within a human-defined class, the system can be treated as autonomous in a critical function.

### 4. Time and space
Temporal/spatial separation matters.

A human can program the mission at 09:00 while the system makes engagement decisions at 12:00 in a changed environment.

A definition therefore needs to avoid a nominal human action becoming a loophole.

### 5. Lethality
The agenda title uses "lethal", but the working text discussed in 2026 moved away from treating actual death as a required condition of characterization.

The practical question is whether scope should capture systems designed to apply force capable of causing lethal effects even when a particular engagement causes only injury or property damage.

### 6. Defensive systems
Some defensive systems act within very short reaction windows. A definition that automatically captures every automated defensive response can make the framework unnecessarily broad.

Scope should therefore be sensitive to:
- target type;
- environment;
- mission;
- operating parameters;
- human control;
- predictability.

### 7. AI decision-support
Target-recommendation systems should not automatically be called LAWS.

However, a framework should address the interface between:
AI recommendations → human authorization → autonomous execution.

Otherwise States could move practical target selection into a decision-support layer and argue that the weapon itself remains "human controlled."

## Scope tests

A future framework could combine:
1. capability-based characterization;
2. critical-function focus;
3. human-specific-target selection test;
4. exclusions for systems demonstrably outside autonomous force-selection;
5. technology-neutral language;
6. periodic review of emerging capabilities.

## Definition traps

Do not argue:
- all autonomous systems are LAWS;
- all drones are autonomous;
- all AI weapons are LAWS;
- every homing weapon is necessarily a LAWS;
- any human parameter-setting defeats autonomy.

## Research conclusion

The most durable scope approach is **function + capability + context**, not platform labels.
